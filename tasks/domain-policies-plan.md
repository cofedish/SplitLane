# План: доменные политики трафика для Windows

Область изменений — `windows/`. Без доменных правил сохраняется существующая маршрутизация приложений.

## Архитектурные решения

- Доменные правила находятся рядом с правилами приложений. Запись использует schema 3;
  schema 1/2 читаются новой версией, отсутствующая коллекция по умолчанию пуста.
  Старые версии не должны молча принимать неизвестный формат.
- Один `RuleEngine`: managed policy, проверка идентичности, процесс+домен,
  домен без процесса, правило приложения. Точное имя специфичнее wildcard;
  длинный suffix специфичнее короткого. Порядок JSON не определяет приоритет.
- `*.example.com` соответствует поддоменам, но не apex. Нормализуются регистр,
  завершающая точка и IDN.
- DNS evidence ограничены TTL и размером кеша. Несколько живых имён на одном IP
  считаются неоднозначностью: предполагаемое имя не выбирается наугад.
- TCP и UDP используют общий resolver. Для UDP учитывается реальное назначение
  датаграммы, а не фиктивное назначение при BIND.
- `PROXY_ONLY` использует существующий redirect/relay. При отказе proxy прямого
  fallback нет. Постоянный WFP/firewall барьер не реализован: остановленный
  WinDivert не обеспечивает защиту после crash/restart/reboot.
- Строгие NAT-решения не истекают, пока сокет открыт. После CLOSE сохраняется
  ограниченная tombstone для поздних FIN/ACK; потерянная атрибуция распознанного
  строгого назначения также приводит к отказу, а не DIRECT.

## Последовательность

1. Модель, matcher, валидация и совместимость конфигурации.
2. Единый resolver и детерминированный приоритет.
3. TTL/CNAME DNS и интеграция enforcement TCP/UDP.
4. WPF-редактор доменных правил.
5. Диагностика, документация, тесты и итоговая проверка diff.

## Риски и проверка

Неоднозначные shared IP, отсутствие наблюдаемого DNS, ECH/DoH/DoT не позволяют
доказать имя назначения. IPv6 extension headers и неполный TCP DNS требуют
отдельной проверки; отсутствие постоянного барьера при остановке процесса
не должно представляться как обеспеченная fail-closed гарантия.

Проверки включают Core/Engine unit tests, реальные socket-интеграции,
Release build, formatting, аудит NuGet и diff review. Live-стенд использует
конфигурацию в памяти, реальный WinDivert и физические счётчики `pktmon` с
положительным TCP/UDP контролем. Remy и её службы не останавливаются.

Подробные фактические результаты: `windows/docs/DOMAIN_POLICY_VALIDATION.md`.
