# SplitLane 0.14.7

- Исправлено ошибочное назначение HTTP CONNECT/SOCKS5 при общем IP нескольких доменов. Перехваченные TCP-соединения сохраняют исходный IP и порт, а TLS/SNI передаётся без изменений. Ранее DNS-догадка могла приводить к ошибкам сертификатов Claude Desktop при инспекции Kaspersky.
- Служба получает уведомление о пробуждении и восстанавливает сетевое состояние с повторными попытками. Явно остановленная пользователем маршрутизация остаётся остановленной.
- Блокировка и разблокировка сеанса не останавливают системную службу. Повторное уведомление об интерактивном пробуждении не вызывает второй перезапуск.
- Убрана настройка подстановки DNS-имён в адрес назначения; старые конфигурации продолжают читаться.

## Проверка на Windows-АРМ

С включённым KES проверить несколько запусков Claude, Win+L/разблокировку, сон/пробуждение и повторный доступ через прокси. Проверить службу SplitLane, новый PID/версию после обновления и журнал engine. Приёмка физического сна/Win+L не заменяется модульными тестами. После сна старые соединения могут оборваться; новые должны устанавливаться автоматически. Для HTTP-прокси отдельно проверить разрешение CONNECT к IP.

Корпоративная редакция сохраняет текущую подпись и канал Nexus testing; переход на будущий корпоративный сертификат в этот выпуск не входит. Публичная редакция сохраняет свой ключ подписи update manifest и GitHub-канал. Доверие Windows и политики KES не отключаются.
